**Ошибки, которые стоит исправить в первую очередь**

Ниже «воспроизведено» означает проверку вызовом текущих функций, а «по коду» — установленную причину или риск без воспроизведения полного пользовательского сценария.

**1. Повторное применение формул и фильтров после открытия экспорта. Приоритет P1. Воспроизведено для формулы.**

При исходном значении `10` и общей формуле `2*x` сохраняется `20`, а после открытия экспортированного CSV отображаемое значение становится `40`. Экспорт сохраняет обработанные значения и активные настройки; импорт игнорирует `data_mode=applied_to_data` и восстанавливает формулу. Аналогичный путь повторно включает сохранённый фильтр.

Исправление: различать применённую обработку и рецепт обработки. Для уже обработанных значений сохранять рецепт как сведения о происхождении, но не активировать его повторно. Проверять несколько последовательных циклов сохранения и открытия.

**2. Чужие имена, видимость и формулы при экспорте части каналов. Приоритет P1. Воспроизведено.**

Пример: есть каналы A и B, A скрыт. CSV содержит только значения B. При импорте метаданных единственный канал становится A и оказывается скрыт. Причина: данные выгружаются по списку выбранных каналов, а метаданные используют номера всех каналов исходного набора. Та же адресация используется для локальных формул.

Исправление: заранее построить единый план экспорта с отображением исходного ID в номер столбца файла. Использовать его для данных, названий, формул, цветов и ссылок маркеров. Проверки: выгрузка только второго/последнего канала, произвольного подмножества и всех каналов.

**3. Искажение FFT при ограничении количества отсчётов. Приоритет P1. Воспроизведено.**

Синус 400 Гц, частота дискретизации 1024 Гц, 32768 отсчётов: без ограничения получен пик 400 Гц с амплитудой 1; при лимите 16384 — пик 112 Гц с амплитудой 1. GUI использует именно этот лимит. Выбрасывание каждого второго отсчёта без предварительного подавления высоких частот вызывает наложение спектров.

Исправление: для точного анализа сохранять исходную частоту дискретизации — считать выбранный непрерывный участок либо весь диапазон в фоне. Если нужна передискретизация, предварительно применять соответствующий ФНЧ и явно показывать изменившуюся полосу анализа. Выбор метода и размера FFT должен быть виден пользователю.

**4. Разная временная шкала в полной и частичной загрузке. Приоритет P1. Воспроизведено.**

Для времени `0, 1, 11, 0, 1` полная загрузка с обычной подготовкой GUI даёт `0, 1, 11, 12, 13`; оконная загрузка — `0, 1, 11, 21, 22`. Полная нормализация использует медианный положительный шаг, сканирование и оконная загрузка — последний положительный шаг. Разрыв перед сбросом времени меняет результат.

Исправление: общий нормализатор времени для полного чтения, предварительного сканирования и чтения по индексу. Хранить границы секций и причины коррекции. Не считать наличие заголовка гарантией монотонности: сейчас для оконной загрузки нормализация секционных timestamp обходится.

**5. Пустая ячейка времени сдвигает каналы. Приоритет P1. Воспроизведено.**

Исправление: до разбиения удалять только окончание строки; пробелы обрабатывать внутри ячеек. Сохранять пустые поля и одинаково валидировать строки в scan/read. Добавить диагностику пропущенных строк и отсутствующих значений.

**7. Исключения внутри фоновой загрузки не перехватываются. Приоритет P1. Риск по коду.**

`try/catch` окружает создание `std::thread`, но не работу внутри лямбды. Исключение при выделении памяти в парсере, копировании каналов или сортировке может завершить процесс. Потоки запускаются через `detach()`, поэтому их завершение и владение результатами при закрытии приложения явно не управляются.

Исправление: перехватывать исключения внутри worker-функции, возвращать структурированный результат; хранить управляемую задачу с отменой и определённым завершением. Не читать состояние UI из рабочего потока. Проверить отказ выделения памяти, отмену, закрытие окна и невозможность публикации результата. OOM/закрытие не воспроизводились в рамках аудита.
